# 01 曝光与视频 AE

> 学习目标：能把“视频忽明忽暗、人脸太黑、进屋反应慢”转成有时间基准、可复现、能区分原因的测试。本文以最终录制视频为主要评价对象；预览另测。用例是教学设计，不是任何厂商内部规范或统一验收阈值。

## 1. 手机视频里需要评价什么

AE 自动曝光决定曝光时间、增益等采集参数，成片亮度还受局部色调映射、人脸处理、HDR、编码和显示影响。评测应分别回答：稳定后亮度是否合适，变化过程中是否自然，为获得亮度付出了多少运动模糊、噪声或帧率代价。

DXOMARK 把视频曝光作为独立属性，并同时观察亮度表现、适应过程与稳定性；这支持我们同时测试稳态和过渡，而不能只截取稳定后的最好一帧。[DXOMARK 方法说明](https://www.dxomark.com/what-we-test-camera/)

| 层次 | 观察内容 | 手机高频问题 |
|---|---|---|
| 稳态结果 | 人脸/主体亮度、背景层次、高光剪切、暗部可辨性 | 逆光脸黑、夜景过亮、肤色灰暗 |
| 动态控制 | 响应延迟、收敛时间、过冲、振荡、平滑性 | 出门后先过曝、亮度抽动、人物进出画面引发跳变 |
| 采集取舍 | 曝光时间、增益、帧率及动态细节 | 画面变亮但运动拖尾，低照帧率下降 |
| 模式一致性 | 录像启停、HDR、防抖、变焦/切摄 | 按录像键变暗，切摄产生亮度台阶 |

## 2. 从亮度曲线读懂一次变化

先用独立事件标记确定光照改变时刻 t0，再测主体或灰阶 ROI 的亮度序列。输出码值 Y′ 可用于描述成片变化，但它不是线性场景亮度；不同传递函数、范围或 HDR 映射下不能直接比较平均码值。

- **响应延迟**：从 t0 到测量量开始显著变化的时间，显著变化门限应超过测量噪声。
- **收敛时间**：从 t0 到指标进入预先定义的稳定带，并连续保持指定时长。报告稳定带、保持时长及参考终值。
- **过冲**：超出终值的最大偏离；必须说明用码值、L* 还是相对变化量。
- **稳态波动**：稳定窗口的标准差、峰峰值，连同 ROI 和窗口报告。
- **曝光准确性**：按有参考的灰阶/场景亮度和明确定义的曝光误差测量；不能简单把处理后 Y′ 的倍数换成 EV。

Imatest Color/Tone 可输出亮度、曝光误差等时间曲线。其文档明确区分响应时间测量与最终曝光准确性；软件默认稳定窗口和阈值属于算法设置，不能直接当作产品通过线。[Imatest AE](https://docs.imatest.com/24.2/auto-exposure)

## 3. 实验室测试如何搭建

使用稳定、可调、已测量的照明，放置灰阶/色卡及人脸主体；手机固定，记录照度、光谱或色温、光比、距离、视场占比、分辨率、帧率、HDR 和防抖状态。变光时尽量维持光谱不变，防止把 AWB 变化混入 AE；若模拟真实场景共同变化，需明确记录。

先测默认相机实际交付效果，再用可控工具做诊断。手动锁曝光的对照能检验某些假设，但第三方应用可能走不同处理路径，其结果不能直接代表厂商相机。预览可用外部记录或厂商调试路径留证，屏幕录制本身可能改变负载与颜色，不应替代原片。

分析时同时保留全局、人脸、背景和高光 ROI。人物移动时要跟踪同一主体，避免固定 ROI 被背景替换而产生假亮度跳变。每个条件先做数次重复，逐条保留失败样本；正式样本量按偶发率和项目要求制定。

## 4. 面向手机的用例起步表

| 用例 | 条件与动作 | 证据与判断重点 |
|---|---|---|
| AE-01 稳态亮度 | 三脚架下分别录明亮、室内、低照灰阶与人脸 | 稳定段亮度、噪声、剪切；同一显示条件下看主体 |
| AE-02 明暗阶跃 | 固定构图，改变灯光强度，明转暗、暗转明分别录 | 独立 t0、亮度曲线、过冲、恢复、曝光元数据 |
| AE-03 逆光人像 | 人物在窗前移动，保持相机与背景不动 | 人脸跟踪 ROI、背景高光、局部映射跳动 |
| AE-04 构图扰动 | 稳定光下让黑/白物体进入画面，再退出 | 排查测光构图敏感性；不同视场占比分开记 |
| AE-05 边走边变光 | 从室外进入走廊，记录路线和步速 | 实际观感、曝光过渡、防抖与运动模糊的交叉 |
| AE-06 录制及切摄 | 预览到录像、暂停恢复、跨摄像头变焦 | 启动亮度台阶与持续时长；区分预览和保存文件 |
| AE-07 帧率压力 | 同场景比较支持的 30/60 fps、HDR 开关 | 是否用曝光时间或降帧换亮度，动态主体是否更糊 |

## 5. 工程日志如何辅助定位

若调试环境支持，可读取曝光时间、感光度、帧持续时间、AE 状态及时间戳，对齐到实际图像。Android CaptureResult 定义这些结果字段及状态含义，但设备能力、字段可用性和应用路径需要核实。状态显示已收敛也不能取代对保存视频的观察。[Android CaptureResult](https://developer.android.com/reference/android/hardware/camera2/CaptureResult)

诊断顺序建议：检查是否光源本身波动 → 核验原片而非播放器自动亮度 → 看全局还是局部变化 → 对齐曝光参数 → 排查 HDR/色调映射 → 用受控对照缩小范围。锁住 AE 后变化消失是支持证据，不足以证明某一算法代码错误。

## 6. 常见误判与练习

- 平均亮度相同，不代表人脸曝光和高光保留相同；应分别看关键区域。
- 响应越快并非总越好：运动摇摄中，过于敏感的控制可能导致亮度不断追逐背景。
- 不把照度变化导致的正常适应、PWM 频闪和算法振荡混称为“AE 闪烁”。
- 高亮区域被压暗，可能来自局部映射；仅凭图像不能断定曝光时间变了。

练习：录制一段“稳定→变暗→稳定→变亮→稳定”视频，标注两次 t0，分别画主体与背景亮度曲线。写出“稳态结果、过渡表现、运动代价”三条结论，并列出缺少什么证据才能判断根因。

## 7. 学习资料与阅读顺序

1. [DXOMARK：Camera 测试说明](https://www.dxomark.com/what-we-test-camera/)——先看 Video 的 Exposure，理解属性范围。
2. [Imatest：Auto Exposure，24.2 文档](https://docs.imatest.com/24.2/auto-exposure)——学习曲线、收敛定义与 CSV/JSON 输出；操作以安装版本为准。
3. [Imatest：Temporal Analysis of Video Files](https://docs.imatest.com/docs/temporal-analysis-of-video-files)——理解抽帧、ROI 与时间分析边界。
4. [Android：CaptureResult](https://developer.android.com/reference/android/hardware/camera2/CaptureResult)——检索 SENSOR_EXPOSURE_TIME、SENSOR_SENSITIVITY、CONTROL_AE_STATE。
5. [AOSP：Camera ITS tests](https://source.android.com/docs/compatibility/cts/camera-its-tests)——学习曝光、测光区域及结果一致性的功能验证。ITS 官方定位是功能符合性测试，不能代替整机视频画质评价，也不等于 vivo、华为、小米、OPPO、三星内部流程。
