# 03 视频 AF 与主体跟踪

> 学习目标：分清“选对主体、保持识别、镜头合焦、平滑切换”四个问题，能测合焦过程并设计跟踪场景。测试建议不代表厂商内部流程，也不提供未经依据的通过阈值。

## 1. 视频对焦为什么不能只测一次速度

手机视频 AF 需要持续判断目标距离、调整镜头，并与主体识别、AE、防抖及多摄切换协作。某些摄像头可能是固定焦点：应先查实际模式与能力，再决定测 AF 还是测可用景深。

“人脸框一直在”只说明检测/跟踪结果可能存在，不保证焦平面正确；主体清晰但切换很突兀，也可能是视频体验问题。DXOMARK 的视频 AF 关注不同光照下的速度、准确性和人脸跟踪，可据此建立持续场景。[DXOMARK AF 范围](https://www.dxomark.com/what-we-test-camera/)

| 子问题 | 典型现象 | 证据 |
|---|---|---|
| 目标选择 | 想拍近处人物，却转向背景 | 主体框、触控操作、前后景清晰度 |
| 合焦准确性 | 已稳定但人物持续虚 | 同条件最佳可达清晰度参照、目标 ROI |
| 跟焦能力 | 人物迎面走来时反复落后 | 距离/动作记录、清晰度时间曲线 |
| 恢复与抗干扰 | 短暂遮挡后长时间对在背景 | 遮挡起止、主体重现、恢复时刻 |
| 过渡品质 | 拉风箱、跳焦、突然快速切换 | 正常播放、焦点变化与镜头位置 |
| 视角副作用 | 对焦时画面像在轻微变焦 | 固定场景特征点的尺度变化 |

焦点呼吸是对焦引起的视角/放大率变化；焦点振荡是合焦控制反复来回。两者可以同时出现，记录时不要互相替代。

## 2. 客观指标怎样定义

- **响应/合焦时间**：从可验证的触发时刻到进入清晰度目标区间；触控触发与物距改变触发应分开测。
- **稳态清晰度比**：同场景最终清晰度相对最佳可达参考的比值。参考应尽量匹配曝光、图卡尺度、锐化与运动条件。
- **跟焦有效时间占比**：在可见、可评价的主体时间内，满足项目定义清晰度判据的时长占比。需剔除完全遮挡等不可判定段并公开规则。
- **失焦恢复时间**：从主体重新可用到恢复合焦；不从遮挡刚开始计时。
- **焦点振荡次数/幅度**：给定窗口内反复变化的次数及清晰度或镜头位置幅度，说明检测门限。
- **呼吸幅度**：固定机位和场景下对焦变化前后的图像尺度差；先排除 EIS 动态裁切、数码变焦与切摄。

Imatest 用 SFR 清晰度指标随时间变化分析 AF，文档建议一次只截取一个调整事件，并指出速度曲线不能单独证明准确性。分析区间没有可用斜边时，应标为无效而非强行算分。[Imatest Autofocus Speed](https://docs.imatest.com/docs/autofocus-speed)

## 3. 实验室与实景如何互补

实验室可用两段距离的斜边/纹理目标建立可重复近远切换；保持目标对比度、大小、照明和几何条件有记录。移动目标的清晰度既受离焦又受曝光模糊影响，应加入短曝光或静止位置对照。用 SFR 时需跟踪有效斜边 ROI，避免运动后测到不同内容。

实景补充不同肤色、戴眼镜、侧脸、回头、多人交叉、宠物和弱纹理。只有实际支持相应识别的产品才测试其功能承诺；其他情况评价默认 AF 表现。实验室指标易复现，但不能覆盖全部主体选择与语义场景。

## 4. 手机视频 AF 起步用例

| 用例 | 条件与动作 | 证据与重点 |
|---|---|---|
| AF-01 近远切换 | 固定机位，前景目标退出露出远景，再反向 | 事件时刻、前后景 ROI、合焦/振荡 |
| AF-02 迎面跟焦 | 人物沿标定路径接近和远离手机 | 速度、距离、主体尺度、跟焦有效时间 |
| AF-03 遮挡恢复 | 目标被短暂遮挡，再按相同位置出现 | 遮挡持续时间、背景抢焦、恢复过程 |
| AF-04 多人交叉 | 两人不同距离交叉，明确预期主体 | 检测框、切换逻辑、是否无故跳焦 |
| AF-05 弱光弱纹理 | 降低照明，使用低反差物体及人脸 | 失败频次、最长失焦段、AE 曝光变化 |
| AF-06 点击主体 | 同一段录像按标记点选前后景 | 触控事件、焦点变化平滑性、意外曝光跳变 |
| AF-07 长焦与切摄 | 变焦跨模组后对接近主体持续录制 | 切摄时刻、恢复、最近可合焦距离限制 |
| AF-08 静止守焦 | 人物停住，背景有人经过或相机轻微抖动 | 无刺激时是否 hunting，主体是否始终可见 |

重复时用相同路线、速度和入画方式，所有失败片段都保留。手持与三脚架分别记录，避免抖动引发的运动模糊被当作 AF 失败。

## 5. 日志能告诉你什么

Android Camera2 的 AF 模式、状态、触发、镜头焦距位置/焦点距离等字段为诊断提供线索；可用范围取决于硬件和模式。应先核验连续视频 AF 是否启用、是否有点击锁定，再将元数据与成片对齐。AF 状态报告“已对焦”不能作为保存视频清晰的唯一证据。[Android CaptureResult](https://developer.android.com/reference/android/hardware/camera2/CaptureResult)

对内置相机与测试应用的差异要单独建记录：相同硬件不意味着采用同一主体识别、调参和成片处理。AOSP ITS 的镜头移动等测试可启发功能验证，其公开页面明确说明 ITS 的功能符合性定位。[Camera ITS](https://source.android.com/docs/compatibility/cts/camera-its-tests)

## 6. 诊断误区与练习

“忽清忽糊”先分四路：焦点变化、运动模糊、时域降噪、防抖/编码。检查镜头位置是否变化只是其中一项证据。触控选择造成 AE 同时改变，也可能让清晰度指标变化。人脸跟踪框消失但主体仍清晰，不能直接判 AF 失败。

练习：录近远切换、迎面运动、遮挡恢复各一组。每组画前景/背景清晰度曲线并标事件；将一次失败写为“现象、发生条件、候选原因、可排除证据、下一次对照”，避免直接写“AF 算法错误”。
