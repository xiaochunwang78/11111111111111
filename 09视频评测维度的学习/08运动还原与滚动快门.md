# 08 运动还原与滚动快门

> 目标：区分曝光运动模糊、滚动快门几何失真和时域处理残影，能设计对应对照实验。本文实验条件为学习建议；手机型号、模式与系统版本必须随样本记录。

## 1. 三种时间问题分别是什么

**单帧曝光期间的运动**会把本应集中在一个位置的信号摊开，表现为沿运动方向的模糊。**不同行在不同时间曝光**会让运动物体在画面不同高度处于不同位置，形成倾斜、弯曲或果冻感。**跨帧处理与融合**可能在遮挡、运动估计错误或权重切换时留下多个轮廓或滞后纹理。

高帧率只说明采样更密，不能直接证明曝光更短或滚动读出更快。拍到倾斜的栏杆也不直接说明传感器故障：它可能是当前读出模式的正常局限，最终是否可接受需要结合场景与产品目标。

## 2. 可用指标及近似关系

| 指标 | 方法 | 限制 |
|---|---|---|
| 模糊宽度 | 匀速高对比边缘的展宽，报告像素或角度 | 受光学模糊、对焦、锐化影响；必须有静态基线 |
| 运动细节损失 | 相同区域静态/运动 SFR 或纹理指标对照 | 移动方向与边缘方向要匹配；不能以噪声高分冒充纹理 |
| 滚动读出偏移 | LED 时序图案或受控运动下的行间位置差 | 要标定光源时序和取景覆盖，不可随意拿风扇估 ms |
| 几何失真 | 直线倾斜、曲率、分区运动残差 | 镜头畸变、EIS 和视差会混入结果 |
| 残影持续 | 遮挡/离开后仍保留轮廓的帧数及毫秒数 | 用呈现时间换算；不能把所有残影都归因于 TNR |

在**匀速投影、近似恒定曝光**条件下，模糊宽度可粗估 $B\approx v_{img}t_{exp}$，其中 $v_{img}$ 为像素/秒，$t_{exp}$ 为秒。简单匀速横移模型中，上下行位置差约为 $\Delta x\approx v_{img}t_{read}$。这些是诊断近似，不适合直接套入强透视、旋转、加速或 EIS 已校正的画面。

Android `SENSOR_ROLLING_SHUTTER_SKEW` 描述行曝光开始的时间偏移，且有有效阵列、裁切和合并读出相关说明；读取它时必须核对输出覆盖范围。[1] 元数据是辅助证据，不能替代最终视频测量，也不能假定原生相机可导出它。

## 3. 公开测量机制怎样迁移到手机

Image Engineering 的 LED-Panel 用已知 LED 时序测曝光和读出相关时间；官方手册给出滚动快门模式与取景要求。[2][3] Imatest 的线性运动装置通过控制图卡速度，测运动模糊及滚动快门效应。[4] 手机实验可借鉴“输入可控、重复动作、静态对照”的思路，不能用未校准的显示器跑马灯冒充精密计时装置。

低成本练习可以用有尺寸标记的直线移动物体与固定手机，测相对变化；要给绝对毫秒数，需校准时间和空间基准。设备配置需记录焦段、分辨率、帧率、HDR、防抖和裁切，模式改变可能切换传感器读出方式。

## 4. 手机测试用例

| 用例 | 条件与动作 | 看什么、留什么 |
|---|---|---|
| MOT-01 移动图卡 | 三脚架固定，图卡匀速横移，另拍静态基线 | 边缘展宽、纹理指标、运动速度与快门 |
| MOT-02 摇摄建筑 | 远处竖直线条，按固定角度/时间摇摄 | 上下行倾斜，保留相机运动与输出对应关系 |
| MOT-03 低照人物 | 人物按标记横穿，比较不同照度 | 连续模糊、多个轮廓、脸部细节；保留完整过程 |
| MOT-04 遮挡恢复 | 手从纹理背景前经过并退出 | 残留轮廓、恢复帧数、背景重新出现后的细节 |
| MOT-05 HDR 运动 | 高光背景前横移主体，HDR/SDR 对照 | 融合重影与边缘破碎；同时核对快门和帧率 |
| MOT-06 防抖联动 | 同一受控运动，普通/增强防抖对照 | 倾斜校正是否带来局部拉扯或裁切波动 |
| MOT-07 模式覆盖 | 同机重复支持的分辨率/帧率组合 | 读出和运动细节是否随模式变化，不能仅比标称 fps |

## 5. 诊断顺序

先问“单帧内连续摊开，还是多个相离轮廓”，再问“整个画面一致，还是只有运动边缘/局部区域”，最后看“是否随曝光、读出模式、防抖或 HDR 切换变化”。这些特征用于提出假设，不构成单一根因证据。

如果缩短曝光后模糊变轻但倾斜依然存在，说明曝光运动与行间时间差可能同时存在。若静态目标也在周期性形变，继续检查相机运动、防抖与支架振动。若只在视频转发后出现重影，先回到原片核对编码或插帧链路。

AOSP 的传感器融合测试检查图像和陀螺仪时间对齐，适合学习如何把图像运动与传感器运动对应起来；它不是自动输出所有运动伪影根因的工具。[5]

## 6. 自主练习

固定手机拍同一移动图卡，至少比较明亮/低照和静态/运动四组。挑一条边缘记录宽度与位置，再选一个遮挡事件记录恢复时间。输出结论分三栏：已观察、可能机制、下一步对照。没有标定时只写相对变化，不给绝对读出速度。

## 7. 学习资料

1. [Android CaptureResult：SENSOR_ROLLING_SHUTTER_SKEW](https://developer.android.com/reference/android/hardware/camera2/CaptureResult#SENSOR_ROLLING_SHUTTER_SKEW)：先核对字段定义、单位及裁切说明。
2. [Image Engineering：LED-Panel](https://www.image-engineering.de/en/products/measurement-devices/led-panel/)：了解计时硬件能测哪些量，别把硬件能力混同完整协议。
3. [LED-Panel V5 官方手册](https://www.image-engineering.de/content/products/equipment/measurement_devices/led_panel/data/LED-Panel_V5_manual.pdf)：查 rolling shutter 和 exposure time 测量设置；注意手册版本。
4. [Imatest：Motion Generators](https://www.imatest.com/equipment/motion-generators/)：学习可控运动目标、运动模糊与读出实验。
5. [AOSP：Camera ITS tests](https://source.android.com/docs/compatibility/cts/camera-its-tests)：搜索 `sensor_fusion`，看同步证据、装夹错误与失败分析。
6. [DXOMARK × CIVIT：视频与计时测量](https://corp.dxomark.com/catalog/services/custom-testing/dxomark-civit-joint-lab-finland-camera-testing/)：确认商业测量中的 ERS、时域变化与帧率范围，勿推断内部阈值。
