# 02 色彩与视频 AWB

> 学习目标：能区分光源估计、颜色还原、肤色偏好和视频颜色稳定性，并建立可复现的色彩测试。下面的场景与指标组合是工程学习建议，不是厂商公开验收表。

## 1. AWB 只是视频色彩的一部分

AWB 根据场景估计照明并选择白平衡校正；最终颜色还经过颜色矩阵、色调/饱和度处理、肤色保护、HDR 映射、编码和显示。灰卡中性但肤色不自然，可能是后续颜色处理；同一个灰卡变色，也可能是照明、曝光或显示解释发生了变化。

DXOMARK 将颜色与白平衡适应列在视频 Color 属性下。对手机测试，建议将“稳态白平衡、颜色/肤色、过渡、空间一致性、多摄一致性”分别记录，避免一个总色差掩盖失败场景。[DXOMARK 视频颜色说明](https://www.dxomark.com/what-we-test-camera/)

## 2. 需要掌握的概念与指标

| 项目 | 推荐观察或量化 | 使用限制 |
|---|---|---|
| 中性区域偏色 | 参考白点下的 a*、b* 或色度偏差；按约定计算中性色差 | 必须明确白点、RGB→XYZ 转换、参考与色适应条件 |
| 颜色准确性 | 色卡逐色块 ΔE00、均值及较差色块；单列肤色块 | 色卡参考需适配光源；平均值不能替代肤色判断 |
| CCT 相关色温 | K 或其变化曲线 | 单一色温不能描述偏绿/偏品红；远离普朗克轨迹的光源不宜仅用 CCT |
| 动态 AWB | 响应延迟、收敛、过冲、色度轨迹、稳态漂移 | 先规定变化触发点与稳定带，AE 联动需记录 |
| 颜色空间均匀性 | 中心/边缘中性色、不同位置的人脸表现 | 避免把照明不均匀或镜面反光误当成色彩阴影 |
| 多摄一致性 | 同主体跨切换点的中性与肤色变化 | 需要匹配视场和 ROI，先分离亮度变化 |

Imatest 的 AWB 文档用色温相关时间曲线描述适应速度，并提示该测量不能单独证明最终白平衡准确性。成片测试应增加中性色和肤色的稳态检查。[Imatest AWB](https://docs.imatest.com/docs/auto-white-balance)

## 3. 实验室怎么控制变量

固定手机、色卡、灰卡与人脸/肤色对象的位置。测量光源照度、光谱或色温与偏离程度；相同 CCT 的 LED 与日光不一定产生相同相机颜色，光谱差异不能忽略。照明应均匀、稳定，避免色卡反光与老化。

先做单光源，再做光源切换，最后做混合光。切换实验可设定暖光→中性光→冷光，但要记录实际测得的光源，不凭灯具面板标称。若希望只研究 AWB，尽量保持照度和构图稳定；研究真实出入室内，则允许照度和光谱同时变化，但必须将它作为联合场景。

处理保存视频时记录色彩原色、矩阵、范围、传递函数。HDR 素材应在正确链路中分析；不能拿 SDR 截图代替 HDR 原片测色。显示评价关闭会随环境改变颜色的屏幕功能，并记录屏幕白点、亮度和环境光。

## 4. 手机场景用例

| 用例 | 条件与动作 | 留存证据与重点 |
|---|---|---|
| AWB-01 单光源基线 | 不同已测光源下录灰卡、色卡、人脸 | 各色块与肤色 ROI、中性偏差、稳定段重复性 |
| AWB-02 冷暖切换 | 固定主体与照度，按标记切换两种光源 | 光源 t0、色度时间轨迹、过冲与恢复 |
| AWB-03 混合光人像 | 窗光与室内灯共同照明，人物左右移动 | 人脸两侧颜色、背景取舍、是否局部闪变 |
| AWB-04 单色主导 | 红墙/绿植等大色块逐渐进入和离开视场 | 灰卡是否随构图被误校正；重复进出路径 |
| AWB-05 低照肤色 | 降低照度，保持光源光谱和人物动作 | 偏色、色噪声、肤色失饱和与跨帧漂移 |
| AWB-06 录制及多摄 | 录像前后、广角到长焦、前后摄可用模式 | 同物体颜色跳变；注明保存视频与预览差别 |
| AWB-07 特殊光源 | 商场、舞台彩灯、霓虹环境 | 是否应保留环境氛围；人为定义参考意图后判断 |

这里不应预设所有灯光下都要“灰卡绝对无色”。某些场景有保留暖光氛围的产品意图；应把自然性偏好与中性准确度分成两项，并结合目标用户与项目要求建立评价锚点。

## 5. 手机算法与公开厂商资料怎样读

Google 曾公开低照手机摄影中学习式 AWB 的背景，说明复杂照明下“物体本色”和“光源颜色”存在歧义。这是理解困难场景的原理资料，介绍的是特定时期的 Night Sight 照片系统，不能据此认定所有手机录像采用同样算法或测试流程。[Google Research 原文](https://research.google/blog/night-sight-seeing-in-the-dark-on-pixel-phones/)

Android CaptureResult 中的 AWB 状态、颜色增益与变换等可以辅助分析，但状态收敛只说明相应控制结果；厂商内置相机还可能进行额外处理。将 Android API 工具与系统相机作对照时，必须标明两条路径，不能把两者输出混为一组数据。[Android 结果元数据](https://developer.android.com/reference/android/hardware/camera2/CaptureResult)

## 6. 常见误判、诊断与练习

- 先核查素材的色彩解释，避免把范围/传递函数错误当作 AWB 偏色。
- 色卡平均 ΔE 变好，但肤色更差时，应单独列出肤色样本及变化方向。
- 快速暖冷变化可能来自 AWB，也可能是灯光闪烁、多摄切换或局部映射；检查时序与控制变量。
- 在相机屏幕上观察的颜色受到屏幕本身影响，最终报告必须保留原片。
- 不要将一帧的色温误差直接推广为“视频白平衡不稳定”；稳定性需要连续时间证据。

练习：在固定灰卡和人物构图下拍两次暖冷光切换；记录中性、肤色、背景三组 ROI。回答：哪组最先改变、是否同向、是否存在阶段性偏绿、每次是否复现。至少提出两个不同根因假设，并设计能区分它们的对照。

## 7. 学习资料

1. [DXOMARK：Camera 测试说明](https://www.dxomark.com/what-we-test-camera/)——阅读 Video Color 的范围。
2. [Imatest：Auto White Balance](https://docs.imatest.com/docs/auto-white-balance)——掌握时域曲线的输入、输出和准确性边界。
3. [Imatest：Auto Exposure](https://docs.imatest.com/24.2/auto-exposure)——比较 AE 与 AWB 的联合分析入口，理解二者联动。
4. [Android：CaptureResult](https://developer.android.com/reference/android/hardware/camera2/CaptureResult)——检索 CONTROL_AWB_STATE、COLOR_CORRECTION_GAINS、COLOR_CORRECTION_TRANSFORM；字段能力依设备而定。
5. [Google Research：Night Sight](https://research.google/blog/night-sight-seeing-in-the-dark-on-pixel-phones/)——理解低照光源估计的歧义；属于照片算法背景资料。
6. [AOSP：Camera ITS tests](https://source.android.com/docs/compatibility/cts/camera-its-tests)——参考 AWB metering 等功能用例的构造；不将 ITS 通过等同于肤色优秀。
