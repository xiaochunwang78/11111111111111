# 09 帧率、帧间隔与连续性

> 目标：把“60 fps 仍卡顿”“录制中突然降帧”“预览卡但成片正常”转成可验证证据。本章命令用于分析原片，不改写素材；示例不是实测结果。

## 1. 分清四条时间轴

手机视频至少涉及传感器采集、图像处理/编码、文件呈现、显示播放。文件 PTS 主要告诉播放器何时呈现帧；DTS 与解码顺序有关。若存在帧重排，解码顺序与呈现顺序可能不同。屏幕刷新率和播放器实际显示也可能改变观看节奏。

因此，文件时间戳异常是线索，不能独自证明传感器丢帧；文件帧间隔整齐也不能证明每帧都是独立采样。重复内容、插帧或重写时间戳可能掩盖采集异常。Android 的传感器时间戳与帧时长字段可以提供另一层证据，但要确认时间基准以及是否确实对应所测应用和流。[1]

## 2. 该统计什么

对按呈现顺序排列的有效时间戳，定义 $\Delta t_i=t_i-t_{i-1}$。名义 30 fps 的间隔约 33.33 ms，29.97 fps 则略有不同，不能强行按同一个精确常数判定。

| 项目 | 建议输出 | 限制 |
|---|---|---|
| 实际平均呈现率 | $(N-1)/(t_{N-1}-t_0)$，单位 fps | 这是该时间段的呈现统计，不等于传感器独立采样率 |
| 间隔分布 | 中位数、分位数、极值、直方图 | VFR 需要结合模式设计解释 |
| 局部节奏 | 滑动窗口帧率与异常时间点 | 长时间平均值会掩盖短促卡顿 |
| 内容连续性 | 受控运动目标位移、外部时间编码 | 静态场景相同像素不证明重复帧故障 |
| 缺失/重复证据 | 时间戳、内容、采集/编码日志互证 | 容器插帧或转码可改变证据 |
| 长录变化 | 温度、时间、设置与局部帧率对应 | 未固定环境不能直接断言热降频 |

Apple 的公开设置说明低照下 Auto FPS 可降低录制帧率以改善质量。[2] 这说明“设置 30 fps 后出现更低帧率”可能符合所启用策略；应先记录开关、环境和机型，再判断是否违背需求。

## 3. 用 FFprobe 检查原片

先保存原始文件，不通过社交软件中转。下面命令要求本机已安装 FFprobe；字段与输出以版本为准。[3]

```powershell
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,r_frame_rate,avg_frame_rate,time_base,duration,nb_frames -of json "sample.mp4"
ffprobe -v error -select_streams v:0 -show_frames -show_entries frame=pts_time,best_effort_timestamp_time,duration_time,pict_type -of json "sample.mp4" > "sample_frames.json"
```

`r_frame_rate` 与 `avg_frame_rate` 都不是独立采样真实性证明。若 `pts_time` 缺失而使用 `best_effort_timestamp_time`，必须标记为解码器估计值。不要未经检查把输出行号当采集顺序；缺失、重复和非单调时间戳应分别记录。

先在自然播放中标出异常段，再分析该段前后的时间戳和内容位移。对高分辨率高帧率文件，换一个确定有足够解码能力的平台复看，以排除播放端瓶颈。屏幕录制会额外引入采样和编码，不能替代原片时间轴。

## 4. 手机测试用例

| 用例 | 条件与动作 | 证据及判断 |
|---|---|---|
| FPS-01 稳态基线 | 固定光照录制有持续运动的目标，覆盖支持的 fps | 文件参数、时间戳、位移序列，不用静态墙面判断重复帧 |
| FPS-02 明暗变化 | 光照阶跃变化；分别开关自动低照帧率 | 降帧时刻、快门、目标位移、恢复行为 |
| FPS-03 长时间录制 | 控制室温、电量与存储，记录温度和时间 | 局部帧率、热状态、文件分段；按项目目标设时长 |
| FPS-04 复杂运动 | 树叶/流水/运动纹理，保持相同模式 | 编码压力与帧节奏是否共同变化 |
| FPS-05 变焦切摄 | 录制中跨过切摄区域并返回 | 对齐切换事件、时间戳和内容，检查短冻结 |
| FPS-06 预览/成片 | 外部录像记录预览，同时留手机原片 | 区分预览显示问题与保存视频问题 |
| FPS-07 播放对照 | 同一原片在手机及另一可靠播放器播放 | 仅某平台卡顿时查解码/显示；保留播放设置 |

## 5. 平台验证与产品评测

AOSP Camera ITS 有时间戳、预览掉帧及多特性组合相关验证入口，并明确其定位是功能测试。[4] 项目中应保存 Android 版本、CTS/ITS 版本和适用能力条件；通过 ITS 不等于所有原生相机模式均无卡顿。

LED 计时装置可以让画面携带独立时间信息，补足容器时间戳的局限。[5] 其测试也要正确设置频率与记录长度，避免混叠或相位关系造成误读。对于无硬件条件的练习，持续匀速目标能提供相对位移证据，但不是绝对计时标定。

## 6. 练习与报告

录制三段：稳定照明、明转暗、暗转明。交付每段原片、模式截图、间隔分布、局部帧率图和异常事件表。把结论写成“文件在第 X 秒附近出现较长呈现间隔，运动内容也发生跨步”，并列出还缺哪些采集/编码证据；不要直接跳到“sensor 丢帧”。

## 7. 学习资料

1. [Android CaptureResult](https://developer.android.com/reference/android/hardware/camera2/CaptureResult)：查 `SENSOR_TIMESTAMP`、`SENSOR_FRAME_DURATION` 及时间源定义。
2. [Apple：调整视频录制设置](https://support.apple.com/en-ie/guide/iphone/iphc1827d32f/ios)：查 Auto FPS，建立“自动降帧也可能是设计行为”的测试前提。
3. [FFprobe 官方文档](https://ffmpeg.org/ffprobe.html)：查 `show_frames`、`show_entries` 和输出格式；命令字段以安装版本为准。
4. [AOSP：Camera ITS tests](https://source.android.com/docs/compatibility/cts/camera-its-tests)：查 jitter、preview frame drop、feature combination，注意版本适用范围。
5. [Image Engineering：LED-Panel](https://www.image-engineering.de/en/products/measurement-devices/led-panel/)：了解独立时序测量设备；进一步阅读该页链接的手册。
